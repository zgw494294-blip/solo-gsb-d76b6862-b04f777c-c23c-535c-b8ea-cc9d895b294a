# 齿轮系转速求解台

基于 **Python / FastAPI** 后端与**原生 HTML/CSS/JavaScript** 前端的齿轮系转速联立求解 Web 应用。
全部运算使用 Python `fractions.Fraction` 以**有理数精确**完成，不引入浮点误差。

## 功能

- 录入 **2～12 根**唯一整数编号的轴，可随时增删改。
- 录入 **1～24 条**传动关系，支持三种类型：
  - **外啮合**：`za·ωa + zb·ωb = 0`
  - **内啮合**：`za·ωa − zb·ωb = 0`
  - **行星组**（太阳轮 s、齿圈 r、行星架 c）：`zs·(ωs−ωc) + zr·(ωr−ωc) = 0`
- 录入 **1～4 个**已知转速，支持有符号整数或分数字符串（rpm），如 `120`、`-3/2`。
- 完整校验并集中报错：未知轴、关系内轴不互异、齿数超出 1～500、非法分数、分母为 0、轴编号重复、数量越界等。
- `POST /api/solve` 对“传动关系 + 已知转速”组成的线性方程组做精确高斯–若尔当消元（RREF）：
  - **无解（inconsistent）**：存在矛盾方程 `0 = 非零常数`，并给出**冲突定位**（见下节）；
  - **唯一解（unique）**：每根轴给出最简有符号分数（分母恒为正），分子、分母以十进制
    整数字符串返回，任意位数的大整数都不丢精度；
  - **欠定（underdetermined）**：按轴录入顺序选主元，非主元轴作为自由变量 `t₁, t₂, …`，
    每根轴显示精确仿射表达式，如 `ω₅ = 1/3 + 2·t₁ − 1/5·t₂`。
- **无解冲突定位**：每条通过校验的传动关系、已知转速都视为一条可追溯条件，按
  “先关系、后已知转速”的录入顺序排列。原模型无解时，从后往前逐条试删——只有剩余
  条件仍无解才永久移除——最终得到确定的**不可再缩减冲突集**：集合本身无解，删去其中
  任一条即有解（不保证条数最少）。判定全程使用有理数。响应返回每条冲突条件的类型与
  原始序号（从 1 开始），页面同步高亮并列出对应输入。
- **目标转速配齿**（`POST /api/gear-options`）：在当前齿轮系中选定一条传动关系的一个
  齿数字段（外/内啮合选 `za`/`zb`，行星组选 `zs`/`zr`）、目标轴与目标转速（有符号整数或
  分数，rpm），其余录入保持不变；后端将所选齿数依次替换为 **1～500** 的整数，逐一用
  有理数求解。候选模型矛盾（无解）即舍弃；即使整体欠定，只要目标轴转速不依赖任何自由
  变量且精确等于目标值也保留该齿数。返回全部匹配齿数及精确目标转速，按“与原齿数差的
  绝对值、齿数”升序排列；无匹配时返回空列表，页面明确提示。页面上点选某个齿数即可
  回填到原关系、清除旧求解结果，其他输入一律不动。
- **理想传动转矩平衡**（`POST /api/torque-balance`）：在现有轴与传动关系上录入
  **1～12 项**已知外加转矩（有符号整数或分数，N·m）并选择 **1～12 根**待求转矩轴；
  同一轴不能同时已知和待求，其余轴外加转矩视为 0，已知转速不参与此计算。按无损、
  无惯性的理想传动建模：关系系数矩阵 `A` 满足 `Aω = 0`，对其零空间的任意允许运动
  `v`，外加转矩向量 `τ` 均须满足 `τ·v = 0`。用有理数精确求待求轴转矩，区分
  **无平衡解 / 唯一解 / 欠定**；欠定时按轴录入顺序列出自由变量及各待求轴的精确
  仿射表达式（见下文“理想传动转矩平衡”一节）。
- **传动链路追踪**（`POST /api/transmission-paths`）：从现有轴中选择起点与终点，
  只沿用轴与传动关系校验（不使用转速或转矩）。每条关系是独立的一步：外/内啮合
  连接 `a`、`b` 两轴，行星组作为同一个关系连接 `s`、`r`、`c` 三轴（组内任意两轴
  一步可达，不拆成三条啮合）；同一对轴间的并行关系分别计数。以经过的关系数为
  路径长度做 BFS，返回**最短链路总数**、按每步“关系录入序号、到达轴录入序号”
  **字典序最小**的一条链路（每步写明关系类型、两端角色与齿数），以及所有最短
  链路**必经的关系序号**。起终点同轴时返回一条长度为零的空链路；不连通时返回
  零条并说明。页面上所选链路经过的关系蓝色高亮、必经关系绿色高亮（见下文
  “传动链路追踪”一节）。
- **啮合谐波重合诊断**（`POST /api/mesh-harmonics`）：复用轴、传动关系与已知
  转速的全部校验，按 `f = za·|ωa|/60` Hz（外/内啮合）与 `f = zs·|ωs−ωc|/60` Hz
  （行星组）精确计算各关系啮合基频；模型无解时返回与 `/api/solve` 相同的冲突
  定位。欠定时基频仍依赖自由变量的关系标为“未确定”且不参与比较，其余关系给出
  精确基频；对每条确定且非零的基频取 **1～12 次谐波**，按精确频率分组，只列出
  包含至少两条不同关系的重合组（组内按关系录入序号、谐波次数排序）。页面上
  参与重合的关系紫色高亮（见下文“啮合谐波重合诊断”一节）。
- **最少制动轴方案**（`POST /api/brake-plans`）：从现有轴中选择**目标轴**
  （制动后在所有允许运动中转速恒为零）与**保护轴**（必须保持可转，即存在其
  转速非零的允许运动），并勾选**可制动轴**（不得包含前两者）；只使用轴与
  传动关系校验，不使用已知转速或转矩。对可制动轴的每个子集追加相应轴的
  `ω = 0` 约束，与外啮合、内啮合、行星组三类关系组成齐次有理数方程，按
  RREF 判定有效性；枚举全部子集（含空集），返回**制动轴数最少**的所有有效
  方案——方案内按轴录入顺序，方案间按该顺序的轴列表字典序排列；空集有效时
  返回含一个空集合的方案列表，无方案时明确说明（见下文“最少制动轴方案”
  一节）。
- 任何输入发生变更即自动清除旧结果，避免展示过期答案。

## 一条命令启动

需要本机已安装 Docker（含 Compose v2 插件）。

```bash
docker compose up --build
```

启动后在浏览器访问：

> **http://localhost:8000**

服务监听容器内 **8000 端口**并映射到宿主机同名端口。
停止服务：在终端按 `Ctrl+C`；后台运行可改用 `docker compose up --build -d`，停止用 `docker compose down`。

## 本地（非 Docker）开发运行

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn backend.app.main:app --reload --port 8000
```

## API 说明

- `POST /api/solve`：对当前录入做精确联立求解（唯一解 / 欠定 / 无解冲突定位）；
- `POST /api/gear-options`：目标转速配齿，枚举一个齿数字段 1～500 筛选匹配齿数
  （见下文“目标转速配齿”一节）；
- `POST /api/torque-balance`：理想传动转矩平衡，精确求解待求轴外加转矩
  （见下文“理想传动转矩平衡”一节）；
- `POST /api/transmission-paths`：传动链路追踪，求最短链路总数、字典序最小链路
  与必经关系（见下文“传动链路追踪”一节）；
- `POST /api/mesh-harmonics`：啮合谐波重合诊断，各关系基频的 1～12 次谐波按
  精确频率找跨关系重合（见下文“啮合谐波重合诊断”一节）；
- `POST /api/brake-plans`：最少制动轴方案，枚举可制动轴子集求制动轴数最少的
  全部有效方案（见下文“最少制动轴方案”一节）。

`POST /api/solve`，JSON 请求体：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }],
  "relations": [
    { "type": "external",  "a": 1, "b": 2, "za": "20", "zb": "40" },
    { "type": "planetary", "s": 2, "r": 3, "c": 1, "zs": "20", "zr": "60" }
  ],
  "known": [
    { "shaft": 3, "speed": "0" }
  ]
}
```

- 外/内啮合字段：`type`、`a`、`b`、`za`、`zb`；
- 行星组字段：`type = "planetary"`、`s`、`r`、`c`、`zs`、`zr`；
- 齿数为 1～500 的整数（接受 JSON 数字或整数字符串）；转速接受整数或分数字符串。

成功响应（节选）：

```json
{
  "status": "unique",
  "rank": 3,
  "free_count": 0,
  "values": [
    { "shaft": 1, "fraction": { "num": "-1", "den": "1", "text": "-1" } }
  ]
}
```

响应中**所有分数的 `num`、`den` 均为十进制整数字符串**而非 JSON 数字：多级传动会产生远超
`Number.MAX_SAFE_INTEGER`（2⁵³−1）的大整数，作为 JSON 数字返回时浏览器 `JSON.parse` 会按
IEEE 754 双精度舍入（例如 `-7812500000000000000` 被解析成 `-7812500000000000512`），
字符串则可完整保真；`text` 同时给出精确的分数/整数文本。8 根轴、7 条 `za=500、zb=499` 的
相邻外啮合链在首轴 1 rpm 时，末轴即返回：

```json
{ "num": "-7812500000000000000", "den": "7703779066869753499",
  "text": "-7812500000000000000/7703779066869753499" }
```

欠定时 `status = "underdetermined"`，返回 `free_shafts` 与每根轴的 `expressions`
（常数项 `constant` 及自由变量系数 `terms`，系数同为 `{num, den, text}` 精确分数字符串）；
矛盾时 `status = "inconsistent"`。输入非法返回 HTTP 400：

```json
{ "detail": { "errors": ["关系 2：太阳轮、齿圈、行星架三轴必须互异"] } }
```

## 无解诊断（冲突定位）示例

录入 4 根轴、2 条外啮合与 4 个已知转速：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }, { "id": 4 }],
  "relations": [
    { "type": "external", "a": 1, "b": 2, "za": "20", "zb": "40" },
    { "type": "external", "a": 3, "b": 4, "za": "10", "zb": "10" }
  ],
  "known": [
    { "shaft": 1, "speed": "100" },
    { "shaft": 2, "speed": "10" },
    { "shaft": 3, "speed": "5" },
    { "shaft": 4, "speed": "-5" }
  ]
}
```

由关系 1 与轴 1 转速 100 可推得 `ω₂ = −50`，与已知转速 2（`ω₂ = 10`）矛盾，响应为：

```json
{
  "status": "inconsistent",
  "shafts": [1, 2, 3, 4],
  "message": "方程组出现矛盾方程 0 = 非零常数，该齿轮系无解。",
  "conflict": [
    { "type": "relation", "index": 1 },
    { "type": "known", "index": 1 },
    { "type": "known", "index": 2 }
  ]
}
```

`conflict` 即不可再缩减的冲突集，按“先关系、后已知转速”的录入顺序给出：

- `type`：`"relation"`（传动关系）或 `"known"`（已知转速）；
- `index`：该条件在同类输入中的原始序号，从 1 开始。

上例中关系 2、已知转速 3、已知转速 4 不参与矛盾，已在从后往前的试删过程中被移除；
剩下的 3 条条件本身无解，而删去（或修正）其中任意一条——例如把已知转速 2 改为
`-50`——方程组即恢复有解。页面上“关系 1”“已知 1”“已知 2”三行输入会以红色高亮
标出，并在结果区逐条列出其内容。

## 目标转速配齿：`POST /api/gear-options`

请求体与 `/api/solve` 相同（`shafts` / `relations` / `known`），另加一个 `target`：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }],
  "relations": [
    { "type": "planetary", "s": 1, "r": 2, "c": 3, "zs": "20", "zr": "60" }
  ],
  "known": [
    { "shaft": 2, "speed": "0" },
    { "shaft": 1, "speed": "100" }
  ],
  "target": {
    "relation": 1,
    "field": "zr",
    "shaft": 3,
    "speed": "25"
  }
}
```

- `relation`：传动关系序号（从 1 开始）；`field`：该关系中要枚举替换的齿数字段
  （外/内啮合只能填 `za`/`zb`，行星组只能填 `zs`/`zr`）；
- `shaft`：目标轴编号；`speed`：目标转速，接受有符号整数或分数字符串（rpm），
  如 `25`、`-3/2`；
- 校验规则与 `/api/solve` 完全一致（先整体校验当前录入，再校验 `target`），非法时
  同样返回 HTTP 400 与集中错误列表。

后端把该字段依次替换为 1～500 的整数逐一精确求解。上例中 `ω₃ = 100·zs/(zs+zr)`，
要求行星架恰为 25 rpm，只有 `zr = 60` 命中，响应：

```json
{
  "status": "ok",
  "shafts": [1, 2, 3],
  "relation": 1,
  "field": "zr",
  "target_shaft": 3,
  "target_speed": { "num": "25", "den": "1", "text": "25" },
  "original_teeth": 60,
  "count": 1,
  "matches": [
    { "teeth": 60, "distance": 0, "speed": { "num": "25", "den": "1", "text": "25" } }
  ]
}
```

说明：

- `matches` 每项给出命中的 `teeth`、与原齿数差的绝对值 `distance`，以及该齿数下
  目标轴的**精确**转速 `speed`（`{num, den, text}`，同样是十进制整数字符串）；
- 顺序固定为 `distance` 升序、`teeth` 升序，即最接近原齿数的方案排在最前；
- 候选齿数导致方程组矛盾（`0 = 非零常数`）时直接舍弃；整体欠定时，只要目标轴
  转速表达式中所有自由变量系数为零（不依赖自由变量）且常数项精确等于目标值，
  仍然保留；目标轴本身是自由变量或其转速依赖自由变量时不计入；
- 没有任何齿数命中时 `count = 0`、`matches = []`，页面会在配齿结果区明确提示
  “无匹配齿数”。

再举一个多命中的例子：外啮合 `za·ωa + zb·ωb = 0`，`ωa = 10`，枚举 `za`（原 20）、
固定 `zb = 40`，令目标轴 b 转速为 `-5`：由 `ωb = -10·za/40` 得 `za = 20` 唯一命中；
若 `ωa = 0`，则任何 `za` 下都有 `ωb = 0`，1～500 全部命中，列表按
`20, 19, 21, 18, 22, …`（距原齿数 20 最近优先）排列。

## 理想传动转矩平衡：`POST /api/torque-balance`

在现有轴与传动关系上做理想（无损、无惯性）传动的转矩平衡。请求体含 `shafts` /
`relations`（与 `/api/solve` 相同，校验规则完全复用），另加 `known_torques` 与
`unknown_shafts`；**不需要也不校验已知转速**（已知转速不参与此计算）：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }],
  "relations": [
    { "type": "planetary", "s": 1, "r": 2, "c": 3, "zs": "20", "zr": "60" }
  ],
  "known_torques": [
    { "shaft": 1, "torque": "10" }
  ],
  "unknown_shafts": [2, 3]
}
```

- `known_torques`：1～12 项已知外加转矩，`torque` 接受有符号整数或分数字符串
  （N·m），如 `10`、`-3/2`；同一轴的转矩不可重复给定；
- `unknown_shafts`：1～12 根待求转矩轴编号；同一轴不能同时已知和待求，未列出的
  轴外加转矩视为 0；
- 校验非法时返回 HTTP 400 与集中错误列表（格式同 `/api/solve`）。

建模：关系系数矩阵 `A` 满足 `Aω = 0`，其零空间即允许运动空间；功率平衡要求外加
转矩向量 `τ` 对零空间任意 `v` 满足 `τ·v = 0`（等价于 `τ` 落在 `A` 的行空间中）。
对每个零空间基向量得到一个平衡方程，已知转矩移入常数项后精确求解待求轴转矩。
上例为行星排（`zs = 20`、`zr = 60`），太阳轮轴加 10 N·m，响应为唯一解：

```json
{
  "status": "unique",
  "shafts": [1, 2, 3],
  "known_torques": [
    { "shaft": 1, "torque": { "num": "10", "den": "1", "text": "10" } }
  ],
  "unknown_shafts": [2, 3],
  "zero_shafts": [],
  "nullity": 2,
  "rank": 2,
  "free_count": 0,
  "values": [
    { "shaft": 2, "fraction": { "num": "30", "den": "1", "text": "30" } },
    { "shaft": 3, "fraction": { "num": "-40", "den": "1", "text": "-40" } }
  ]
}
```

即 `τ₁ : τ₂ : τ₃ = 20 : 60 : −80`（`zs : zr : −(zs+zr)`），齿圈轴 30 N·m、行星架轴
−40 N·m。响应中所有分数同样是 `{num, den, text}` 十进制整数字符串；`nullity` 为
独立平衡方程数（`A` 的零空间维数），`zero_shafts` 列出转矩视为 0 的轴。

其余两种状态：

- **欠定**（`status = "underdetermined"`）：平衡方程少于待求轴。例如 4 根轴、两对
  外啮合（1–2：`za=20, zb=40`；3–4：`za=10, zb=10`），已知 `τ₁ = 5`，待求轴
  `[2, 3, 4]`：方程为 `τ₂ = 2τ₁ = 10` 与 `−τ₃ + τ₄ = 0`，响应含
  `"free_shafts": [4]`，各待求轴的精确仿射表达式为 `τ₂ = 10`、`τ₃ = t₁`、
  `τ₄ = t₁`（自由变量按轴录入顺序编号，`expressions` 结构与 `/api/solve` 相同，
  单位为 N·m）；
- **无平衡解**（`status = "inconsistent"`）：已知外加转矩本身与平衡方程矛盾
  （出现 `0 = 非零常数`），例如外啮合对上同时给定不满足传动比的 `τ₁ = 10`、
  `τ₂ = 5`，响应附 `message` 说明；调整已知转矩或重新划分已知/待求轴即可。

## 传动链路追踪：`POST /api/transmission-paths`

在现有轴与传动关系上追踪两轴之间的传动链路。请求体含 `shafts` / `relations`
（与 `/api/solve` 相同，校验规则完全复用），另加 `start` / `end` 两个轴编号；
**不使用也不校验已知转速与转矩**：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }, { "id": 4 }],
  "relations": [
    { "type": "planetary", "s": 1, "r": 2, "c": 3, "zs": "20", "zr": "60" },
    { "type": "external",  "a": 2, "b": 4, "za": "10", "zb": "10" },
    { "type": "external",  "a": 3, "b": 4, "za": "10", "zb": "10" }
  ],
  "start": 1,
  "end": 4
}
```

图模型：每根轴是一个节点，**每条关系是独立的一步**——外/内啮合连接 `a`、`b`
两轴；行星组是同一个关系，连接 `s`、`r`、`c` 三轴，组内任意两轴之间一步可达
（**不拆成三条独立啮合**）；同一对轴之间的并行关系各自独立计数。以经过的关系
数为路径长度做无权 BFS：

- `length`：最短链路长度（经过的关系数）；
- `count`：最短链路总数（按关系序列区分，并行关系分别计数）；
- `path`：按每步“关系录入序号、到达轴录入序号”**字典序最小**的一条最短链路，
  每步写明关系录入序号、关系类型、两端轴编号与角色（`role_label`）及齿数
  （端点字段 `from.teeth` / `to.teeth`：行星架无齿数，为 `null`；每步另附
  `teeth` 汇总该关系的全部齿数）；
- `essential`：所有最短链路**必经**的关系录入序号（升序）。

上例中轴 1 → 轴 4 有两条最短链路（经关系 1 到轴 2 再经关系 2，或经关系 1 到
轴 3 再经关系 3），长度均为 2；第一步两条候选同为关系 1，按到达轴录入序号取
较小的轴 2，响应为：

```json
{
  "status": "ok",
  "shafts": [1, 2, 3, 4],
  "start": 1,
  "end": 4,
  "length": 2,
  "count": 2,
  "path": [
    {
      "step": 1,
      "relation": 1,
      "type": "planetary",
      "from": { "shaft": 1, "role": "s", "role_label": "太阳轮 s", "teeth": 20 },
      "to":   { "shaft": 2, "role": "r", "role_label": "齿圈 r",   "teeth": 60 },
      "teeth": { "zs": 20, "zr": 60 }
    },
    {
      "step": 2,
      "relation": 2,
      "type": "external",
      "from": { "shaft": 2, "role": "a", "role_label": "主动轴 a", "teeth": 10 },
      "to":   { "shaft": 4, "role": "b", "role_label": "从动轴 b", "teeth": 10 },
      "teeth": { "za": 10, "zb": 10 }
    }
  ],
  "essential": [1]
}
```

两条最短链路都经过关系 1（行星组），故 `essential = [1]`；关系 2、3 各自可被
另一条链路绕过，不是必经。页面上所选链路经过的关系行以蓝色高亮，必经关系行
以绿色高亮；修改任何轴或关系后结果自动清空。

特殊情形：

- **起终点同轴**：`status = "ok"`，`length = 0`、`count = 1`、`path = []`、
  `essential = []`，附 `message` 说明存在一条长度为零的空链路；
- **不连通**：`status = "disconnected"`，`count = 0`、`length = null`、
  `path = []`、`essential = []`，附 `message` 说明两轴不在同一连通分量；
- 校验非法（轴/关系规则与 `/api/solve` 一致，或起终点未在轴列表中定义）时
  返回 HTTP 400 与集中错误列表。

## 啮合谐波重合诊断：`POST /api/mesh-harmonics`

请求体与 `/api/solve` 完全相同（`shafts` / `relations` / `known`，校验规则
全部复用），不需要额外参数：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }, { "id": 4 }],
  "relations": [
    { "type": "external", "a": 1, "b": 2, "za": "20", "zb": "40" },
    { "type": "external", "a": 3, "b": 4, "za": "30", "zb": "60" }
  ],
  "known": [
    { "shaft": 1, "speed": "90" },
    { "shaft": 3, "speed": "40" }
  ]
}
```

每条关系的啮合基频按有理数精确计算：外/内啮合 `f = za·|ωa|/60` Hz，行星组
`f = zs·|ωs−ωc|/60` Hz。上例中关系 1 的基频为 `20·90/60 = 30` Hz，关系 2 的
基频为 `30·40/60 = 20` Hz；对每条确定且非零的基频取 1～12 次谐波并按精确
频率分组，30 与 20 的公共倍数 60、120、180、240 Hz 处出现跨关系重合，
响应（节选，共 4 组重合，这里列出首尾两组）：

```json
{
  "status": "ok",
  "shafts": [1, 2, 3, 4],
  "rank": 4,
  "free_count": 0,
  "free_shafts": [],
  "harmonic_max": 12,
  "relations": [
    { "relation": 1, "type": "external", "determined": true,
      "frequency": { "num": "30", "den": "1", "text": "30" } },
    { "relation": 2, "type": "external", "determined": true,
      "frequency": { "num": "20", "den": "1", "text": "20" } }
  ],
  "groups": [
    { "frequency": { "num": "60", "den": "1", "text": "60" },
      "members": [
        { "relation": 1, "harmonic": 2 },
        { "relation": 2, "harmonic": 3 }
      ] },
    { "frequency": { "num": "240", "den": "1", "text": "240" },
      "members": [
        { "relation": 1, "harmonic": 8 },
        { "relation": 2, "harmonic": 12 }
      ] }
  ]
}
```

说明：

- `relations` 按关系录入顺序给出每条关系的基频：`determined = true` 时
  `frequency` 为精确频率（`{num, den, text}` 十进制整数字符串，单位 Hz）；
  欠定模型中基频仍依赖自由变量的关系 `determined = false`，不参与重合比较；
- `groups` 只列出包含至少两条不同关系的重合频率，按频率升序；`members`
  按“关系录入序号、谐波次数”升序给出该频率处各关系的谐波次数；基频为 0
  的关系不产生谐波，不参与分组；
- 模型无解时返回与 `/api/solve` 相同的 `status = "inconsistent"` 与不可再
  缩减 `conflict` 冲突集；输入非法同样返回 HTTP 400 与集中错误列表；
- 页面上各关系基频以表格列出、重合组逐组展示，参与重合的关系在录入区以
  紫色高亮；任何输入变更即清空诊断结果。

## 最少制动轴方案：`POST /api/brake-plans`

在现有轴与传动关系上选择制动目标。请求体含 `shafts` / `relations`（与
`/api/solve` 相同，校验规则完全复用），另加 `target` / `protected` /
`brakeable`；**不使用也不校验已知转速与转矩**：

```json
{
  "shafts": [{ "id": 1 }, { "id": 2 }, { "id": 3 }, { "id": 4 }],
  "relations": [
    { "type": "planetary", "s": 1, "r": 2, "c": 3, "zs": "20", "zr": "60" },
    { "type": "external",  "a": 4, "b": 2, "za": "10", "zb": "10" }
  ],
  "target": 4,
  "protected": 3,
  "brakeable": [1, 2]
}
```

- `target`：目标轴编号——制动后它在**所有允许运动**中转速必须恒为零；
- `protected`：保护轴编号——必须**保持可转**，即存在一条保护轴转速非零的
  允许运动；目标轴与保护轴必须互异；
- `brakeable`：可制动轴编号数组（顺序任意，重复或包含未知轴、目标轴、
  保护轴均报 HTTP 400）；不勾选任何轴时传空数组 `[]`（此时仅评估空集）。

判定（全部有理数精确完成）：关系齐次方程 `Aω = 0` 的解空间即允许运动空间；
对可制动轴的每个子集 B，把其中每根轴的单位约束 `ω_j = 0` 追加到关系行后做
RREF——目标轴在所有允许运动中恒为零，当且仅当它的主元行是只在目标列取 1 的
单位行（单位行已落在行空间）；保护轴仍能非零转动，当且仅当它是自由变量或其
主元行仍含非零自由变量系数。

上例是“行星排 + 外啮合”的复合轮系：制动齿圈轴 2 后，行星排上太阳轮 1 与
行星架 3 仍可联动，而轴 4 经外啮合 `10·ω4 + 10·ω2 = 0` 与齿圈同锁；
空集（不制动）与单独制动轴 1 都不能锁死轴 4，故唯一最少方案是制动轴 2：

```json
{
  "status": "ok",
  "shafts": [1, 2, 3, 4],
  "target": 4,
  "protected": 3,
  "brakeable": [1, 2],
  "candidate_count": 4,
  "min_brakes": 1,
  "count": 1,
  "plans": [[2]],
  "message": "共枚举 4 个候选制动集合：最少需要制动 1 根轴，有 1 个并列最优方案；……"
}
```

说明：

- `candidate_count`：枚举的候选集合数（`2^可制动轴数`，始终含空集）；
- `min_brakes`：最少制动轴数；`plans`：所有并列最优方案，每个方案是一个
  制动轴编号数组，**方案内按轴录入顺序，方案间按该顺序的轴列表字典序
  排列**；`count` 为方案数；
- **空集有效**（关系本身已强制目标轴恒为零，例如两根轴间存在两条不同
  传动比的并行啮合 `20ωa+40ωb=0` 与 `20ωa+30ωb=0`，同时保护轴是可自由
  转动的另一根轴）时 `min_brakes = 0`、`plans = [[]]`——返回含一个空
  集合的方案列表；
- **无方案**时 `status = "none"`、`min_brakes = null`、`plans = []`，
  附 `message` 明确说明枚举了全部子集仍无任何集合同时满足“目标轴恒零、
  保护轴可转”；
- 目标轴与保护轴相同、可制动轴重复、编号未在轴列表中定义等输入非法时
  返回 HTTP 400 与集中错误列表，格式同 `/api/solve`。
